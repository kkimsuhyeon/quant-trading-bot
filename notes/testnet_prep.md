# Testnet 준비 체크리스트 (집에서 준비할 것)

> 목적: **가짜 돈으로 진짜 거래소 주문 기계장치를 리허설**하는 단계. 실거래(real money) 아님.
> 검증 사다리: 백테스트✅ → 섀도우(신호 로깅)✅ → **testnet(가짜돈·진짜주문)** → 소액 실거래 → 확대.

## ★ 먼저 알아야 할 핵심 (기대치 정렬)
- **testnet은 "배관(plumbing)"을 검증하지, "캐리가 돈 버는가(경제성)"는 검증 못 한다.**
  - 바이낸스는 **현물 testnet과 선물 testnet이 분리된 환경**(잔고·API키 따로) → 캐리의 *양다리 헷지*를 testnet에서 진짜처럼 묶기 어렵다.
  - **testnet 펀딩은 합성(가짜)** → 캐리의 수익원(펀딩) 경제성은 testnet으론 확인 불가. 그건 소액 실거래에서만.
- **그래서 testnet 1순위 타깃은 캐리가 아니라 *추세전략(단일 다리, 롱/현금)*** 이 맞다. 추세 실행엔진(한 다리)이 단순하고 testnet에서 의미 있다. 캐리 양다리는 그다음.

## 1. 계정·API 키 준비 (바이낸스 testnet)
- [ ] **선물 testnet**: `testnet.binancefuture.com` 가입 → API Key/Secret 발급(거래 권한). 가짜 USDT 자동 충전됨.
- [ ] **현물 testnet**: `testnet.binance.vision` (별도 계정·별도 키).
- [ ] (추세전략만 먼저 할 거면 **선물 testnet 키 하나면 충분** — 현물 testnet은 캐리 단계에서.)
- [ ] 키는 `.env`에 저장(이미 `.gitignore`에 .env 포함). **절대 커밋 금지.**
- [ ] ccxt는 `exchange.set_sandbox_mode(True)`로 testnet 연결 지원 — 코드에서 키만 갈아끼우면 됨.

## 2. 가져올 결정 (집에서 정해서 알려줄 것)
- [ ] **첫 타깃 전략 1개** (추천: 추세 중 Keltner 또는 Regime — 단일 다리, 검증됨).
- [ ] **주문 방식**: 시장가(market) vs 신호봉 종가 근처 지정가(limit). (섀도우는 "다음 봉 시가 체결" 가정이었음.)
- [ ] **포지션 크기**: testnet은 가짜라 명목값(예: 0.01 BTC 또는 고정 notional). 실거래 가면 가드레일대로 손절·한도 필수.
- [ ] **실행 주기**: 기존 섀도우 cron 타이밍 재사용(4h봉 마감 +10분).

## 3. 실행 엔진이 갖춰야 할 것 (앞으로 만들 것 — 미리 알아두기)
섀도우(`paper_trade.py`)의 신호·멱등·락 패턴을 재사용하되, **로깅 대신 실제 주문**을 추가:
- [ ] 주문 제출(시장/지정) + 체결 확인 + 현재 포지션 조회
- [ ] **의도 포지션 vs 실제 포지션 정합성(reconcile)** — 어긋나면 보정/경보
- [ ] 에러·재시도·타임아웃, 멱등성(중복 주문 방지), 단일 실행 락(이미 있음)
- [ ] **킬스위치**(가드레일 5: 최대손실 한도 도달 시 정지) — testnet부터 습관화
- [ ] 주문/체결/포지션 로그(나중 감사용)

## 4. 순서 (현실적)
1. **추세 1전략 → 선물 testnet** (단일 다리 실행 배관 검증) ← 여기부터
2. 캐리 양다리 → 현물+선물 testnet (배관만, 경제성은 제한적)
3. **소액 실거래**(Phase 6, 가드레일 충족 후) — 여기서야 캐리 경제성·실제 슬리피지·basis가 나옴
4. 확대

## 5. 정직한 한계 (반복)
- testnet이 잘 돌아도 "돈 번다"가 아니라 "주문 기계가 작동한다"까지다.
- 캐리 경제성·거래소 위험(FTX식)·실제 basis/슬리피지는 testnet 밖. 소액 실거래에서만 진짜 드러남.
- 지금 펀딩은 낮은 레짐(2026-06 Extreme Fear, BTC 최근30일 연 ~2.5%) — 캐리는 레짐 지나가며 천천히.
